# Project constraints

- Never upgrade, replace, or reconfigure the system Flutter SDK while working on this repository.
- Do not lower the package's Flutter/Dart requirements to bypass local verification failures. Report incompatible or missing SDKs explicitly.
- Standard verification commands are documented in `.github/workflows/ci.yml` and `doc/RELEASE_CHECKLIST.md`.
- iOS sources and RunnerTests can be type-checked with the installed Xcode compiler and an existing Flutter simulator framework without running Flutter or modifying its SDK. RunnerTests also needs Xcode's platform-specific Developer/usr/lib XCTest Swift overlay on the import path. Type-checking is not a substitute for runtime tests.
- Native XCTest subsets can run independently of Flutter tooling: build a temporary `.xctest` bundle with an Info.plist/CFBundleExecutable using `xcrun --sdk iphonesimulator swiftc -emit-library -enable-testing -module-name native_feed_player`, the plugin Swift sources, and RunnerTests. Pass RunnerTests by absolute path so its local video fixture resolves correctly. Link the existing Flutter simulator framework and XCTestSwiftSupport; include Xcode's simulator Developer/usr/lib overlay and public/private XCTest framework rpaths. A same-module testable-import warning is expected for this temporary bundle, not for the normal project build.
- Run the temporary bundle with `xcrun simctl spawn <simulator-id> <Xcode-Developer>/Platforms/iPhoneSimulator.platform/Developer/Library/Xcode/Agents/xctest -XCTest native_feed_player.ManualPlaybackRecoveryTests <bundle.xctest>`. `CacheRegressionTests` uses isolated fixture directories. Do not run tests that clear shared caches against real user caches. These native logic tests do not replace Flutter plugin integration or physical-device playback tests.
